# Organizations Implementation Design

## Goal

Group multiple admins under a shared organization with a shared Google Calendar, role-based permissions, an invite flow, and org-aware booking with priority-based admin selection.

## Architecture

### Rename in existing code (done before new development)
- `app/models/customer.py` → `app/models/user.py`, class `Customer` → `User`, DB table `customer` → `user`
- `credentials_from_customer` → `credentials_from_user` in `app/google_calendar.py`
- All references to `Customer`/`customer` updated throughout routes and tests

### New modules
- `app/models/organization.py` — Organization model (DB table `organization`)
- `app/models/organization_member.py` — OrganizationMember join table (user ↔ org, role, priority)
- `app/models/organization_invite.py` — pending org invites
- `app/auth.py` — `require_auth` decorator + `generate_auth_url` helper
- `app/org/__init__.py`, `app/org/routes.py` — org blueprint (URL prefix `/org`)
- `app/org/email.py` — invite email helper
- `app/org/selection.py` — admin selection logic (freebusy + priority)

### Modified modules
- `app/models/user.py` — add `api_token` field
- `app/main/routes.py` — remove `GET /`; update `GET /callback` to return Bearer token
- `app/booking/routes.py` — `POST /book` uses `org_uid` + optional `user_id`; `GET /confirm-booking/<token>` creates event on both admin and org calendar
- `app/__init__.py` — register org blueprint, import new models
- `migrations/versions/002_add_orgs.py` — renames `customer` → `user` table, adds Organization/OrganizationMember/OrganizationInvite tables + User.api_token

### Tech stack
- Existing: Flask, Flask-SQLAlchemy, Flask-Migrate, Flask-Mail, google-api-python-client, dnspython
- No new dependencies

## Authentication

### How it works
- `User.api_token` is generated by `secrets.token_urlsafe(32)` after a successful OAuth flow.
- Protected routes require `Authorization: Bearer <token>` header.
- `require_auth` decorator in `app/auth.py` looks up the user by token and attaches it to `flask.g.current_user`. Returns `401` with a fresh Google OAuth URL if missing or invalid.
- `GET /` is **removed**.

### `GET /callback` (modified)
After OAuth completes and credentials are saved, generate (or regenerate) `api_token` and return:
```json
{"token": "<api_token>"}
```

### `require_auth` decorator
```python
def require_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        auth_header = request.headers.get('Authorization', '')
        token = auth_header.removeprefix('Bearer ').strip()
        user = User.query.filter_by(api_token=token).first() if token else None
        if not user:
            return jsonify({'error': 'Unauthorized', 'auth_url': generate_auth_url()}), 401
        g.current_user = user
        return f(*args, **kwargs)
    return decorated
```

`generate_auth_url()` builds a fresh Google OAuth URL using `build_oauth_flow()` moved to `app/google_calendar.py`.

### Protected routes
- `POST /org/register`
- `POST /org/<org_uid>/invite`
- `PUT /org/<org_uid>/users/<user_id>`
- `POST /book`

### Public routes (no auth required)
- `GET /callback` — this IS the auth endpoint
- `GET /org/<org_uid>/join/<token>` — invitee clicking email link
- `GET /org/join-callback` — OAuth redirect target for invite flow
- `GET /confirm-booking/<token>` — guest clicking booking confirmation link
- `GET /get-busy-hours` — read-only, unchanged

## Organization Registration

### `POST /org/register` (protected)
Body: `{ "org_name": "..." }`

Steps:
1. Verify `g.current_user` has no existing `OrganizationMember` record (cannot register a second org).
2. Call Google Calendar API `calendars().insert(body={"summary": org_name})` using the user's credentials to create the shared calendar.
3. Call `acl().insert()` to grant the user owner access to the new calendar.
4. Create `Organization(name=org_name, google_calendar_id=<new_calendar_id>)`.
5. Create `OrganizationMember(org=org, user=g.current_user, role='owner', priority=1)`.
6. Return `{"org_uid": org.id, "calendar_id": org.google_calendar_id}`.

## Invite Flow

### `POST /org/<org_uid>/invite` (protected, manager+)
Body: `{ "invitee_email": "...", "role": "employee", "priority": 1 }`

Steps:
1. Load `OrganizationMember` for `g.current_user` in the org identified by `org_uid`. Must be `owner` or `manager`. `403` otherwise.
2. Managers can only assign role `employee`. Owners can assign any role including `owner` (promote) and can demote another owner.
3. Check no `OrganizationMember` exists for `invitee_email`. Return `400 "User already belongs to an org"` if so.
4. Check no existing non-expired `OrganizationInvite` for `(org_id, invitee_email)`. Return `400 "Invite already pending"` if so.
5. Create `OrganizationInvite(org_id, invited_email, role, priority, token=secrets.token_urlsafe(32), expires_at=utcnow+24h)`.
6. Send invite email with link `<BOOKING_CONFIRM_BASE_URL>/org/<org_uid>/join/<token>`.
7. Return `200 {"message": "Invite sent to <email>"}`.

### `GET /org/<org_uid>/join/<token>` (public)
1. Look up `OrganizationInvite` by token. `404` if not found.
2. Verify invite belongs to `org_uid`. `400` if mismatch.
3. Check not expired. `410` if expired.
4. Store token in `session['org_invite_token']`.
5. Build OAuth flow with `redirect_uri=/org/join-callback`.
6. Redirect to Google OAuth URL.

### `GET /org/join-callback` (public — OAuth redirect target)
1. Complete OAuth, fetch credentials and email from Google.
2. Retrieve `session['org_invite_token']`; look up `OrganizationInvite`. `400` if missing or expired.
3. Verify `user_email == invite.invited_email`. `400 "Email mismatch"` if not.
4. Look up existing `User` by email:
   - If exists and already has `OrganizationMember` for the **same org**: update credentials, clear invite, return token. (Re-link case.)
   - If exists and has `OrganizationMember` for a **different org**: return `400 "Already belong to another org"`.
   - Otherwise: create or update `User` with credentials + new `api_token`.
5. Create `OrganizationMember(org_id, user, role=invite.role, priority=invite.priority)`.
6. Grant write ACL on `org.google_calendar_id` for the new member (using org owner's credentials).
7. Delete `OrganizationInvite`. Clear `session['org_invite_token']`.
8. Return `{"token": user.api_token}`.

## Member Management

### `PUT /org/<org_uid>/users/<user_id>` (protected)
Body: `{ "role": "...", "priority": 1 }` — all fields optional.

Permission matrix:

| Actor role | Target | Can update role? | Can update priority? |
|---|---|---|---|
| owner | any other member | yes (any role) | yes |
| manager | employee | yes (`employee` only) | yes |
| manager | manager or owner | no — 403 | no |
| employee | themselves | no | no |

Note: no user delete endpoint in this release. Soft-delete will be added later.

Steps:
1. Load actor's `OrganizationMember` in `org_uid`. Load target's `OrganizationMember` in same org by `user_id`.
2. Apply matrix. Return `403` for violations.
3. Apply updates. `db.session.commit()`.
4. Return `200 {"message": "Updated"}`.

## Booking Changes

### `POST /book` (protected)
Body uses `org_uid` instead of `store_email`; optional `user_id` to pick a specific admin.

```json
{
  "org_uid": 1,
  "user_id": 42,           // optional — pick a specific admin
  "guest_email": "...",
  "guest_name": "...",
  "date": "2024-08-01",
  "start_time": "11:00",
  "end_time": "12:30"
}
```

Steps:
1. Validate fields, parse datetimes, check alignment and duration (unchanged).
2. Look up `Organization` by `org_uid`. `400` if not found.
3. MX-validate `guest_email` (unchanged).
4. Load all `OrganizationMember`s for the org.
5. **Admin selection** (see below). Returns chosen `User` or `409` if none available.
6. Create `PendingBooking` with `admin_user_id` (FK → User) and `org_id` (FK → Organization) instead of `store_email`.
7. Send confirmation email to guest.
8. Return `201 {"message": "Confirmation email sent to <email>"}`.

## Error Reference

| Code | Meaning |
|---|---|
| 400 | Validation failure, org not found, email mismatch, already in org |
| 401 | Missing or invalid Bearer token — includes `auth_url` |
| 403 | Permission denied (role hierarchy violation) |
| 404 | Token not found |
| 409 | No admin available / slot taken |
| 410 | Invite or booking confirmation link expired |
